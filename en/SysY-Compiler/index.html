一.参考编译器介绍：PL/0编译器

1.总体结构

PL/0 编译器是一个相对简单的编译器实现，用于教学目的，以展示编译器的构造原理和基本功能。该编译器包括词法分析、语法分析、语义分析、代码生成以及解释执行等核心模块。编译器采用自底向上的设计方式，首先处理源代码的字符流，逐步构建出抽象语法树，并最终生成代码。

2.接口设计

  • 输入接口

    通过文件输入的方式接收源代码文件，文件名由用户指定。

  • 词法分析接口

    getsym 过程用于从源代码中提取符号，并更新全局符号变量 sym。

  • 语法与语义分析接口

    通过一系列的过程和函数（如 block、statement、expression 等）实现语法和语义分析，构建抽象语法树，并进行符号表的管理。

  • 代码生成接口

    gen 过程用于生成中间代码，代码存储在全局数组 code 中。

  • 解释执行接口

    interpret 过程用于解释执行生成的代码，模拟计算机的执行过程。

3.文件组织

  • 全局变量与常量定义

    定义了编译过程中所需的全局变量、常量以及类型，如符号类型 symbol、对象类型 objecttyp、函数类型 fct 等。

  • 词法分析模块

    getsym 过程及其辅助过程 getch 实现了词法分析功能，从源代码中提取符号

  • 语法与语义分析模块

    包含了一系列的过程和函数，如 block、statement、expression 等，用于实现语法和语义分析，构建抽象语法树，并管理符号表。

  • 代码生成模块

    gen 过程用于生成中间代码，代码存储在全局数组 code 中。此外，还定义了指令格式和指令集。

  • 解释执行模块

    interpret 过程用于解释执行生成的代码，模拟计算机的执行过程，包括栈操作、指令执行等。

  • 主程序

    负责读取源代码文件，初始化全局变量，调用词法分析、语法与语义分析、代码生成以及解释执行等模块，完成整个编译过程。

三.词法分析

编码前设计

1.token

根据教程和理论课，保存代码信息到一个个token中，便于后续分析（不用去再读c源文件）。

2.TokenType

每个token需要有一个辨识方法，我们分类这些token便于使用。

3.lexer

有了token，我们可以开始读文件了。

根据教程，我们可以循环输入字符，通过分支语句完成一个有穷自动机，识别类型后存信息到token。

编码后修改

本次作业比较简单，有穷自动机的构造基本类似，没有出现bug。

四.语法分析

编码前设计

我们已经有了一个个token,根据文法，我们需要分析这些token串，根据理论课，我们采取递归下降法把信息存到文法中非终结符节点中。

1.非终结符结点

为每个非终结符节点写一个类，类属性包含该非终结符的推导规则中的其他结点，类方法包括属性的获取方法等。

2.parser

有了结点类，递归下降分析，为每个结点写一个parse方法，根据文法分析,把parse的结果返回到节点中。
注意要消除推导规则中出现的左递归。

编码后修改

本次作业从头到尾都是递归下降的思路，没有修改。

五.语义分析

编码前设计

我们在上一个阶段后，已经成功获取到了语法树，接下来为了检查变量使用前是否定义和参数数量类型是否匹配等语义分析，我们可以递归下降分析。

1.符号表管理

为每个block、函数块等作用域建立一个符号表，并记录符号表的父亲，记录每个变量名、类型等信息，便于后续使用时查表检查。

为了处理不同种类的符号，对普通变量、数组变量、函数处理方式更独立，写了子类ArraySymbol和VarSymbol、FunctionSymbol,便于处理语义分析。

2.visitor类

  • 局部化错误处理

    有了语法树，我们递归下降分析文法，对每个结点写一个visit方法，根据文法错误类型做局部化错误处理。

  • 符号表写入和查询

    • 查询：当使用ident时，判断标识符是否被定义。
    • 写入：变量声明和函数定义时，写入当前的符号表。

编码后修改

本次作业开始只有普通的符号表，我后续增加了函数独有的符号管理表HashMap<String, FunctionSymbol>functionSymbol来管理函数名Symbol,便于根据函数名找到函数symbol，从而便于检验参数等。

六.LLVMIR代码生成

编码前设计:midend

由于LLVMIR的value核心特性，设计思路是，先区分value类型，再写出所有类型的value类，如module、Function、各种instruction,后续再完善这些value类的属性方法。核心属性是名字、value类型、父亲。

1.LLVMIR的Instruction

这些instructio都是value!!!,其属性继承Value类，还包括一个ArrayList,代表指令类使用的Value

  • Add
  • Alloca
  • Br
  • Call
  • …

2.visitor类

上一阶段的visitor只是语义分析和错误处理，这一阶段我们开始填写并完善每个结点的visit函数，生成LLVMIR语句。

  • curValue

    这个可以说是生成中间代码的关键信息，用于记录当前递归下降分析到的value，在下次visit时，如果需要使用可以令Value tmpValue = curValue先保存上次获得的当前value值（即curValue）。

  • 分析文法的每个推导规则产生的LLVMIR语句

    分析语法树中的每个信息，生成对应的value，通过BuildValue类把分析得到的value保存到Instruction类的使用value中。

3.BuildValue

由于我的Visitor类处理语义分析和错误分析，也包括符号表管理，所以为了思路清晰，我建立了一个BuildValue类用于单独建立Value，便于生成LLVMIR中的Instruction.
